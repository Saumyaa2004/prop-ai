# Book a Site Visit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Buyers book conflict-safe hourly site visits from the AI chat or the listing dialog; the AI only proposes, a human confirms.

**Architecture:** Two new tables (`leads`, `site_visits`) with a partial unique index as the race-proof slot guard. One service (`services/visits.py`) used by a REST router and by two read-only agent tools. The chat response carries a `visit_proposal` built from tool results; the frontend renders a confirmation card that posts name + phone straight to `POST /visits`.

**Tech Stack:** FastAPI 0.143, SQLAlchemy 2.1 (sync) + psycopg 3, Alembic 1.20, pytest; React 19 + TS 6, Vitest 4.

**Spec:** `docs/superpowers/specs/2026-10-14-book-a-visit-design.md`

## Global Constraints

- Run backend commands from `backend\` with `backend\.venv\Scripts\python.exe`. Never read `backend\.env`.
- No new packages. IST = fixed offset `timezone(timedelta(hours=5, minutes=30))` (no `tzdata`).
- Slots: start hours 10–17 IST, today … today + 13 days, strictly after `now`.
- Phone: Indian mobile, 10 digits starting 6–9, optional `+91`/`91`/`0` prefix, spaces/dashes allowed → stored `+91XXXXXXXXXX`. Name 2–100 chars after trim.
- Tests that write use the rollback fixture; only the race test commits, and it deletes its rows.
- The agent gets no write tool. Phone numbers never reach the LLM.
- Before every commit: backend pytest, frontend `npm test`, `npm run build`, `npm run lint` all exit 0. Commit messages via `git commit -F <file>` (no BOM).
- Do not edit `docs/PROGRESS.md` or `docs/INTERVIEW_PREP.md`.
- `alembic upgrade head` needs the owner's approval first (schema change).

## Review Focus

1. Visitor whose browser is not in IST: labels must still show IST hours → `formatSlot("2026-10-18T05:30:00Z")` contains `11:00` (Task 5).
2. `now` exactly at a slot start, or later the same hour → that slot is not offered or bookable (Task 2: `test_slot_starting_now_is_not_offered`).
3. Same person typing their phone differently (`98765 43210`, `+91-98765-43210`, `098765 43210`) → one lead (Task 2: `test_same_phone_any_format_reuses_lead`).
4. The model sends `starts_at` naive, with `+05:30`, or in UTC `Z` → same IST slot (Task 2: `test_parse_slot_accepts_naive_offset_and_utc`).
5. Slot taken or listing sold between proposal and Confirm → 409 with a readable message, and the card reloads slots (Task 3 API tests; Task 6 card behaviour).
