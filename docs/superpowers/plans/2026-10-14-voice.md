# Voice (speech in and out) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a visitor speak a question to the Prop AI chat and optionally hear replies read aloud, with typing always working as the fallback.

**Architecture:** Two small adapters wrap the browser's Web Speech API behind our own interfaces (`SpeechInput`, `SpeechOutput`). They take the `window` object as a parameter, so tests pass fakes and the UI only sees our types. Pure helpers turn chat replies into speakable text and recognition error codes into user messages. `ChatSection` adds a mic button and a "Read replies aloud" toggle on top of the existing `useChat` flow. There are no backend changes.

**Tech Stack:** React 19 + TypeScript 6 (strict, `erasableSyntaxOnly`, `noUnusedLocals`), Vitest 4 (node environment, no jsdom), Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`, `speechSynthesis`), lucide-react icons, existing shadcn `Button`.

**Spec:** CLAUDE.md roadmap item 5, *"Voice — Web Speech API STT/TTS behind small interfaces; text always works as fallback"*, plus the design decisions below (no separate spec doc). Existing code this builds on: `frontend/src/components/ChatSection.tsx`, `frontend/src/hooks/useChat.ts` (`send(text)`, `reset()`), `frontend/src/lib/chat.ts` (`cleanReply`).

**Design decisions (fixed for this plan):**
- **The mic sends automatically on a final result.** The recognised text becomes the user's chat bubble, so what was heard is always visible. While listening, the input box shows the interim transcript.
- **Read-aloud is off by default** and toggled in the chat header (`aria-pressed`). The choice is remembered in `localStorage` under `propai.readAloud`, wrapped in try/catch.
- **Speech output is cancelled** when the mic starts (so the assistant doesn't hear itself), on send, on New chat, when read-aloud is turned off, and on unmount.
- **Recognition language `en-IN`**, for Indian English place names and "lakh/crore". The voice prefers `en-IN`, then any `en-*`, then the browser default.
- **The adapter is created lazily on the first mic click,** not at render. That avoids constructing a recognizer for visitors who never use voice, and lets the headless test inject a fake recognizer after page load.
- **Unsupported browsers** (e.g. Firefox has no `SpeechRecognition`): the mic button is disabled, with the hint "Voice input isn't supported in this browser. Type instead." Read-aloud only shows if `speechSynthesis` exists.
- **Privacy note under the mic:** "Voice is converted to text by your browser's speech service." (Chrome and Edge send audio to their vendor's cloud.)

## Global Constraints

- No new npm dependencies; no backend changes.
- Text chat must keep working exactly as now when voice is unsupported, denied or off.
- The mic never starts without a user click; nothing listens in the background.
- Spoken text comes only from the assistant's reply (after `cleanReply`), never from listing data the model didn't say.
- Recognition `lang = "en-IN"`, `interimResults = true`, `continuous = false`, `maxAlternatives = 1`.
- Spoken text is capped at **600 characters**, cut at the last sentence end (`.`, `?`, `!`) before the cap, or at the cap if there is none.
- All user-visible copy in this plan is exact; use it verbatim.
- Commits: write the message to a file and run `git commit -F <file>`; gate on test exit codes (PowerShell 5.1: check `$LASTEXITCODE`). Don't touch `docs/PROGRESS.md` or `docs/INTERVIEW_PREP.md`.

## Review Focus

1. **Browser without SpeechRecognition (Firefox)** → `createSpeechInput` returns `null`, the mic is disabled with the hint, and typing still works. *Pinned in Task 2.*
2. **Mic permission denied** (`not-allowed`) → a readable message, and the UI leaves "listening". *Pinned in Task 1 (message) and Task 2 (error then end both reported).*
3. **Silence or no result** (`end` without `result`) → back to idle, nothing sent. *Pinned in Task 2.*
4. **Speech overlapping speech** (a new reply arrives while the previous one is still speaking, or the mic opens during speech) → old speech is cancelled first. *Pinned in Task 3.*
5. **Reply text that sounds bad when read raw** (₹ labels, `PAI-DEMO-002`, bullets, very long replies) → natural spoken form, capped length. *Pinned in Task 1.*

**Interfaces:**
- Consumes: nothing from Task 1.
- Produces:
  ```ts
  export interface SpeechInputHandlers {
    onInterim: (text: string) => void;
    onFinal: (text: string) => void;
    onError: (code: string) => void; // SpeechRecognitionErrorCode values
    onEnd: () => void;               // always called last, exactly once per start()
  }
  export interface SpeechInput { start(handlers: SpeechInputHandlers): void; stop(): void; }
  export type SpeechWindow = { SpeechRecognition?: RecognitionConstructor; webkitSpeechRecognition?: RecognitionConstructor };
  ```

**Interfaces:**
- Consumes: `createSpeechInput` (Task 2), `createSpeechOutput(window)` (Task 3), `textForSpeech`, `voiceErrorMessage` (Task 1), `useChat().send/reset/messages` (existing).
  - Call `createSpeechInput(window as unknown as SpeechWindow)`. `SpeechWindow` has only optional properties, and `Window` declares none of them, so passing `window` directly fails TypeScript's weak-type check (TS2559).
  - `createSpeechOutput(window)` needs no cast, because `Window` has `speechSynthesis`.
- Produces:
  - `useVoiceInput(onFinal: (text: string) => void): { supported: boolean; listening: boolean; interim: string; error: string | null; start(): void; stop(): void }`
    - `supported` is computed once from `window`, and the adapter is created lazily inside `start()`.
    - `error` holds the result of `voiceErrorMessage`.
  - `useReadAloud(): { supported: boolean; enabled: boolean; toggle(): void; speak(text: string): void; cancel(): void }`
    - Persists `enabled` in `localStorage["propai.readAloud"]` with try/catch on every access.
    - Cancels speech on unmount, and when toggled off.
